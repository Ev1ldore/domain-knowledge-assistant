# 单实例设计边界

API 不拥有业务分流逻辑。HTTP 与 WebSocket 调用相同问答对象，依次做输入校验、会话串行化、FAQ、混合检索、证据选择/核验、历史持久化。前端只展示服务端结果和状态，不自行构造来源。

SQLite 存 FAQ、sessions、history、files、chunks 和全局知识 revision。文件与片段使用随机文件 ID 和内容相关片段 ID；不使用行业枚举。现有小型知识库的稠密向量以 JSON 存储，查询时归一化后矩阵乘得到余弦分数；同时执行 BM25，RRF 融合候选并执行 CrossEncoder。该实现是真实向量检索，但没有声明具备 Milvus 的规模、过滤或高可用能力。

上传写入独立 UUID 目录并登记 uploaded；一个工作线程转换为 indexing，完成解析和全部嵌入后，在同一 SQLite 事务发布片段和 ready 状态。异常记录 failed；重启遗留的 uploaded/indexing 明确标记中断，等待管理员重建。就绪之外的文件不参与检索。

删除先在事务中删除文件记录及外键级联片段、提升 revision，再清理上传副本。索引任务提交前检查文件记录，删除不会被正在执行的任务复活。问答开始读取 revision，完整证据核验后写历史时再比对；如果期间知识发生改变，返回重试提示，不能保存或流出旧答案。没有跨会话的答案缓存。

同一会话通过有限数量的锁串行处理；不同会话查询仅使用自己 session_id 的历史。明确的连续追问使用紧邻上一轮的有效检索问题补全指代，重新查当前知识库。若上一轮未成功回答，不向更早的旧话题跳转。这里是有限规则的上下文处理，不是通用复杂对话记忆。

模型被要求返回 JSON 证据选择。服务端仅接受已检索 ID 和其中存在的连续原文；无效 ID/非原文/未知状态导致明确失败，不存成功历史，也不透传模型文字。原文仍可能有错误、恶意或与问题关系不足；这层约束不是语义真实性证明。引用 ID 和文件位置由服务端维护，不交给模型生成。

管理员 Bearer token 为进程内随机凭据，2 小时有效，所有管理读写接口都检查鉴权。登录错误限流，没有默认管理员密码。用户会话使用随机不可预测 UUID 作为本地持有者凭据，没有账户层所有权验证，因此只面向本地单用户框架，不可直接开放到公网。
