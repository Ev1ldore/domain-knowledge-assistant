# 证据治理增量迁移

## 迁移前的代码事实与最小方案

检查目标项目后再实施。目标非 Git 工作区，不覆盖 `.local` 或已有数据。

- `rag_qa/core/documents.py:extract/chunks`：PDF 页、PPT 页、Markdown 章节可保存；原 chunk ID 为文件 UUID、片段序号和正文的哈希，无独立文档版本和原文偏移。
- `base/storage.py:Store`：SQLite files/chunks/faq/history，向量为 JSON；所有业务变更共用 revision。没有 MySQL/Milvus 或知识图谱。
- `rag_qa/core/retriever.py:Retriever.search`：SQLite 就绪文档 → NumPy 余弦与 BM25 → RRF → 现有 CrossEncoder；以前只按 ready 过滤，无查询时间、业务范围和文档 ACL。
- `new_main.py:_answer`：FAQ 命中直接返回；文档由模型选连续原文，服务端校验 ID 和 substring 后拼装答案。引用来自服务端，但没有逐结论语义支持审核；不同证据被选择器判断为 clarify，未保留冲突组。
- `app.py`：HTTP 与 WebSocket 共用 answer；已区分索引失败与模型失败；生成完成再发送 token。管理使用既有登录令牌，普通问答无用户认证体系。
- `static/app.js`：现有来源侧栏和安全 DOM 渲染；原文、文件名、页/章节能展示，没有版本、结论状态和复核管理。

最小迁移：复用原项目 EvidenceEngine 及规则测试；为本项目单独实现 SQLite 快照适配、原文定位回填、现有检索适配和兼容响应；在原 UI 上增加信息。没有引入第二种数据库、向量服务、角色扮演系统或答案缓存。

## 运行链路与约束

上传 / FAQ upsert → 现有解析和 embedding → 原文段/偏移/文件内容哈希版本 → SQLite 原索引与证据快照同事务发布 → 问题/日期/范围 → 匿名公共权限过滤 → 已授权 chunk ID SQL 白名单 → 原 dense/BM25/RRF/reranker → 服务端原文和版本复核 → 每子问题候选结论 → 单独模型语义审核 → 冲突兼容性判断 → 有限修复 → 服务端拼正文 → revision 复核 → sources/citations/claims → 历史保存 → WS 最终事件。

FAQ 已进入同一结论和语义校验流程，不再直接回答。FAQ 使用现有本地 BM25，文档继续使用当前 embedding 和 reranker。引用序号由服务端根据当前请求引用白名单生成。

每个证据独立保存 citation_validity 与 usability；每个 claim 保存支持和反驳集合、状态、语义结果及不确定性。supported 表示当前可用证据支持当前结论，不是事实准确率。无法支持的文字在正文及 claim 中删除或替换为无法确认，不能仅删引用。

当前问答身份固定 anonymous；只允许 public 且 tenant 为空的资料。限制资料在检索候选、reranker、模型、引用前排除，后续再次复核。不接受客户端伪造 principal、roles 或 tenant。管理员登录仅用于管理，不能赋予普通问答角色。没有答案缓存；权限、文档、复核更新增加 revision，旧历史正文及引用隐藏并要求重新查询。

未解决同范围冲突保留各方和原文；不同范围先澄清，不因上传较新选边。权威等级及来源说明由管理员提供，系统不据等级自动裁决。origin_id/source_url 归并转载，未知来源统一 unknown-origin，不虚构独立证据数量。模型输入提示注入隔离和白名单不能证明语义判断永不受影响。

## 数据迁移、更新与恢复

`migrations/001_evidence.sql` 只增加 evidence_records、evidence_vectors、evidence_audit，不删旧表、不改向量格式。首次启动 EvidenceStore 自动回填现有 ready 文档：重新提取当前上传副本，仅在原 chunk ID 和正文完全一致时建立定位快照。找不到原文件或匹配失败则 unresolved，返回 unindexed，不能假称有效。后续启动幂等。

版本为上传文件 SHA256，chunk 证据 ID 绑定文档 UUID、版本及片段 ID。locator 为解析后的原文段字符偏移，保留页/幻灯片/章节；不是 PDF 字形坐标。original_segment 和 SHA256 可复核已保存版本的摘录。

PUT `/api/kb/files/{fid}` multipart file 创建该稳定文档 ID 的新版本，旧快照和向量保留；默认不推断旧版本失效，需管理员标注生效区间或明确替代依据。历史查询仍可查旧有效版本。DELETE 文件移除活跃文件与上传副本，证据快照保留为删除历史，普通查询不可使用。FAQ 同问题 upsert 具有明确替代语义，保留旧快照，以更新日期为替代边界（日期粒度，不能区分同一天内的历史）。

旧数据文件、会话和 instance_id 保留。首次迁移增加 revision，因此原历史内容不再作为当前可信回答展示。修改或删除后没有缓存可复用，在途回答 revision 不一致也不发布。

写入目标项目之前在 `.local/evidence-migration-backup-*` 保存被修改源码、变更清单及运行演示库 SQLite 一致性备份。回滚：停止新服务，恢复备份源码；数据库新增表可保留，不影响旧程序读取原表。若需回滚数据也应在停止服务后恢复 SQLite 备份（会丢弃备份之后的新会话/导入）。原管理密码不写入文档或测试报告。

## 接口与使用

原 `/api/query` 的 query/session_id、answer/status/sources 保留；新增可选 `scope` 字符串对象和 `as_of` ISO 日期。例如：

```json
{"query":"课程费用？住宿条件？","scope":{"region":"上海"},"as_of":"2026-09-21"}
```

响应新增 overall_status、claims、citations、conflicts、missing_information、retrieval_status、validation_status、request_id、config_version、cache、query_scope、as_of。旧 status 的 answered/insufficient/error 等保留，增加 partial/conflicted；FAQ 现在由 answered 等表示证据状态，source.type 仍为 faq。answer_mode 改为 evidence_governed。

前端“适用范围与日期”输入地区(region)、产品(product)、日期；其他业务范围可用 API 的 scope 传入。支持结论内数字引用、来源展开版本/偏移/原文/时间、逐结论状态、缺失信息与双方分歧。生成期间 pending；end 事件替换正文及来源，失败事件不得显示已验证正文。

管理登录后“加载证据与复核记录”：编辑版本 metadata JSON + 修正依据；撤销最近修正；对冲突选择一个候选 + 裁决依据；撤销裁决；查看操作人/时间/依据。

- GET `/api/kb/evidence`
- PUT `/api/kb/evidence/versions/{version_id}` body `{policy,reason}`
- POST 同地址 `/undo`
- POST `/api/kb/evidence/conflicts/{group_id}/decision` body `{chosen_claim_id,basis}`
- DELETE 同 decision 地址撤销
- GET `/api/kb/evidence/audit/{record_id}`

沿用 Bearer 管理权限。上传可选 multipart `policy` JSON，在发布索引前设置 ACL/范围，避免先公开再限制。默认公开知识库；FAQ 导入也支持 multipart policy，为本批新版本在同一事务中预置 ACL/范围，权限限制同时作用于其历史版本。

所有日期允许 null，结束日期不包含；superseded_by 是另一个 version_id，同时要求 superseded_at 和 replacement_basis。authority 非 unknown 必須有 basis，转述 source_kind=reported 必须有 speaker。

模型、数据目录、embedding、reranker、管理员凭据仍使用原 config.ini 和环境变量。没有新增外部模型供应商；默认本地 Ollama 模型。固定预算见 evidence.py：最多 2 次混合检索、2 次候选提取、每轮 8 个独立结论审核、4 次冲突兼容性审核；每次模型受 model_timeout 和输出长度约束。

## 已知限制

语义审核依赖模型、可能误拒或漏判；实体/属性/条件对齐目前是结构化模型输出和保守规则，不是完整本体推理。复杂中文多问题分解、跨段联合论证、同义实体、重叠时间区间仍需人工复核。没有校准准确率，不显示置信百分比。

SQLite/NumPy 保留原单实例全量索引设计；检索有限 top_k，可能遗漏低相关冲突。补检是问题拆分后的混合检索，无外部搜索。原始未知范围/时间不能被可靠自动补齐，需管理员标注。证据快照和审计记录会增长，需要部署方规划容量和合规保留周期。
